WHY THE FIRST UPLOAD DID NOT APPEAR

The first ZIP contained a top-level sweetville folder. Because the upload was
performed from inside GitHub's existing sweetville folder, GitHub created:

sweetville/sweetville/

The live site reads the first sweetville folder, so the nested files were not used.

CORRECT UPLOAD — FOLLOW THESE STEPS

1. Extract this corrected ZIP.
2. In GitHub, open the EXISTING sweetville folder.
3. Choose Add file > Upload files.
4. Drag everything shown at the ROOT of this extracted ZIP onto GitHub:

   - index.html
   - mochi.html
   - fun-dipp-splash.html
   - pink-lips-after-dark.html
   - exp42-music-destinations.css
   - exp42-music-destinations.js
   - assets folder

5. Before committing, confirm GitHub shows paths such as:

   sweetville/index.html
   sweetville/fun-dipp-splash.html
   sweetville/pink-lips-after-dark.html
   sweetville/assets/exp42/fun-dipp-waterpark.webp

6. If GitHub shows sweetville/sweetville/ anywhere, cancel the upload.

If GitHub does not accept the assets folder in the main upload, open the existing
sweetville/assets folder and drag only the extracted exp42 folder into it.
